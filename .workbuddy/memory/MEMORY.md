# 写作项目 · 长期约定

## 项目定位

《架构的代价》——互联网、物联网与智能体的六十个判断点。7 篇 31 章，约 27.3 万字。
策划与大纲在 `D:/WorkBuddy/写作/`。

**交付格式：正文、大纲、规范一律 Markdown（.md），不再默认 HTML。**
HTML 只用于「需要给别人看或打印的定稿」，不是工作稿载体。写书要能改、能 diff、能进 Git、能进出版流程——HTML 每次改都要动标签，是反效率。

## 不可动摇的口径

- 书名与副标题已定，不轻易改；副标题的「六十」对应 30 章 × 2 条判断句硬配额（收口章只重述）。
- 动机是个人品牌与行业影响力 → 每章必须产出可单独引用的论断句，可直接做演讲页。
- 两层通吃靠版式（章首卡 / 主论断 / 决策现场 / 边栏 / 章末栏），不靠把内容写浅。
- 十处防重复切分线已钉死：12↔13、5↔25、7↔15、8↔26、9↔18、27↔28-30、20↔23-26、21↔24、22↔16、29↔7。写作只留钩子，不展开。
- 证据标签四类：`公开` / `引用` / `推演` / `场景`。原「实测」「设计态」已取消。
- 脱敏不够，是根本不写：不出现公司数据、案例、口径冲突、制度、产品、客户、供应商、芯片型号、BOM、成本、员工姓名。判定标准是「这话会不会让人反推出某家公司」，会就删，不改写。

## 写作纪律

- 每节必须能回答「所以你不该做什么」；没有否决项的节删掉。
- 收口句只写判断，不写劝告（禁止「大家一定要」「应该重视」）。
- 每章至少一处「这件事我们做得不好」，否则会被读成宣传册。
- 素材不够就写短，不许用「因地制宜」类话术凑篇幅。单章 10,000 字硬上限。
