## 1. 两种语言：判断与证据

| 语言 | 立在哪 | 基本单位 | 回答的问题 |
|---|---|---|---|
| **判断语言** | 章 2 立尺，前三篇使用 | ADR / 降级三档 / 一致性谱系 / 容量假设 / 重试预算 | 为什么是这个方案，为什么不是另一个 |
| **证据语言** | 第四至七篇各自立表 | 质量＝缺陷来源×拦截点；安全＝攻击面×权限面；合规＝覆盖率×有效期；测评＝样本量×判据×签字人；商业＝成本结构×替换成本 | 凭什么说它对，凭什么说它划算 |
| **合一** | 章 31 | 八个视角 × 六十个问题 | 把答案抄走，就是你的架构基线 |

**边界规则**：前三篇出现安全、合规、质量、商业化话题时，只留一行钩子并写 `→ 见第 X 章`，不展开。后四篇出现架构取舍时，只引结论、不复述推演。

违反这条，全书会多出 3 万字重复，读者在第二章就会发现「又是这套」。

## 2. 每章 7 段式

34 章一个模板，不搞例外。模板的价值不是整齐，是让读者第二次读就知道该跳哪里。

| # | 栏目 | 字数（以 9,000 字章为例） | 写什么 | 不写什么 |
|---|---|---|---|---|
| 1 | **章首卡**（浮框） | 120 | 三行：问题是什么 / 主张一句 / 代价一句 | 不写背景、不写感谢、不写"本章将" |
| 2 | 引子 | 600 | 一个具体场景或一句话事故 | **不给结论**。引子里出现答案，后面全是注脚 |
| 3 | **主论断**（加粗独立段） | 60 | 全章唯一一句可引用的话 | 不写第二个论断。两个就是没有 |
| 4 | 你以为 / 实际 / 机理（3–4 组） | 5,000 | 每组 1,200–1,500 字；机理里放数字、配置、算例 | 不写"应该"。写"是什么、为什么会这样" |
| 5 | **决策现场** | 1,500 | 真实取舍 + ≥2 个选项表（代价 / 否决理由 / 谁拍的板） | 不写只对不错的顺风故事 |
| 6 | 代价与边界 | 500 | 什么时候该反过来做 + 我们没做到的部分 | 不写"仅供参考" |
| 7 | **本章栏** | 400 | 判断句 2 条 / 本章的代价 1 条 / 不可外包清单 3 条 | 不重复正文原句 |

### 2.1 三段式的写法

| 段 | 写什么 | 可判定的合格标准 |
|---|---|---|
| **你以为** | 行业里普遍相信、但错了的那句话。要写成一句能被人点头的话 | 读者点头了才算立住。不点头说明你打的是稻草人 |
| **实际** | 真实发生的是什么。必须带可观测的现场特征 | 能写成一个「如果我在现场会看到什么」的画面 |
| **机理** | 为什么必然如此。给数字、给推演、给标准条款 | **去掉数字或条款后这段还成立吗？** 成立就说明你只讲了道理 |

**范本**（可直接复用句式）：

> **你以为**　架构文档就是把最终设计画明白，让人照着做。
> **实际**　半年后设计图还在，但为什么这么设计没人记得。接手的人看到一份"看起来更简单"的方案，会热心地改回去，把同一个坑再踩一遍。
> **机理**　架构知识有三种：结论（用了 Redis）、理由（要扛 5,000 QPS 读）、否决项（试过本地缓存，多实例不一致）。前两种画在图上，第三种只存在人的脑子里——人一走就没了。

### 2.2 收口句三条禁令

- **不写劝告**。「没演练过的降级等于不存在」是判断；「大家一定要演练」是劝告。删掉后者。
- **不写程度词**。「很」「非常」「极其」在判断句里一律无效，它们不改变任何决策。
- **不写套话**。「因地制宜」「结合业务实际」这类句子，删掉后读者损失为零。

## 3. 边栏「给管理者」

两层通吃靠版式，不靠把内容写浅。管理者用 30% 篇幅读完一章，靠的就是这些边栏。

| 项 | 要求 |
|---|---|
| 位置 | 外侧 1/3 版心，每章 2–3 个 |
| 长度 | ≤80 字，三句话，固定句式 |
| 句式 | ① 你该问的一个问题　② 你可以签的字　③ 你不该批的预算 |
| 内容性质 | **后果翻译**，不是摘要。摘要＝重复正文；翻译＝把技术事实换成管理后果 |
| 硬约束 | 每一句在正文里必须找得到出处。找不到，说明边栏是另一个人的文章 |

**示例**（章 7 规模）：

> **你该问：** 上一次固件升级，变砖了几台，谁去现场的？
> **你可以签：** 把 OTA 灰度比例写进发布流程，而不是写进周报。
> **你不该批：** 没有回滚方案、只承诺"升级成功率 99%"的固件项目。

**反例**（不要这样写）：

> "本章讲了规模的三个维度，包括设备数、消息频次和固件版本多样性，企业应结合自身情况重视规模问题。"

这是摘要 + 劝告 + 套话，三种毛病齐了。管理者读完得不到任何可动作的东西。

## 4. 四类证据标签

这本书不写任何公司实际情况，所以证据只有四种。

| 标签 | 用在哪 | 必须附带 | 典型误用 |
|---|---|---|---|
| `公开` | 标准条款、法规条文、监管公告、公开事故报告 | 标准号 / 条款号 / 发布主体与日期 | 把「行业普遍如此」当成公开事实 |
| `引用` | 研究报告、第三方统计、媒体调查 | 机构 + 年份 + 样本量 | 海外结论直接当中国结论 |
| `推演` | 容量、成本、误差复利、失效放大 | 假设清单 + 推翻条件 | 推演写成「我们发现」 |
| `场景` | 复合场景，用于引子与决策现场 | 「由 N 个公开案例重构」一句 | 标了场景却写了可定位信息 |

**硬规则**

- 章 7、13、14、27、29 推演占比最高，**每处推演必须列假设与推翻条件**。只给结论的推演不可反驳，等于口号。
- 章 17–19、20–22、24 依赖标准与法规，**拿不到条款原文就不许写「要求如此」**，只能写「公开资料有限，以下为常见做法」。
- 复合场景一律标 `场景`，并在章末写明由几个公开来源重构。

## 6. 三域对照卡（横切篇专用）

第四至七篇是四个横切，最大的风险是写成四本独立手册。每章末一张卡，强制把话题拉回三域。

| 域 | 本章结论在该域的具体形态（每行 ≤40 字） |
|---|---|
| 互联网 | |
| 物联网 | |
| 智能体 | |

**填不出来的处理**：如果某一域填不出差异，只有两种可能——① 本章话题在该域不存在（那就删掉该行，并在正文说明为什么不存在，这本身是好内容）；② 你没想清楚（那就别写这一章）。

## 7. 篇末刻度表

每篇末半页，只列度量单位，不重述主张。作用是让读者带着"单位"进入下一篇，而不是带着"感想"。

| 篇 | 度量单位 |
|---|---|
| 一 · 互联网 | QPS / P99 / 错误预算 / 副本数 / 连接数 |
| 二 · 物联网 | 在线率 / OTA 成功率 / 变砖率 / 上门次数 / 部署人天 |
| 三 · 智能体 | 端到端成功率 / 单任务成本 / 人工复核率 / 链路步数 |
| 四 · 安全 | 攻击面 / 权限面 / 密钥轮换周期 / 审计完整性 |
| 五 · 合规 | 义务清单覆盖率 / 证据有效期 / 举证响应时长 |
| 六 · 质量与测评 | 缺陷来源占比 / 拦截点 / Cpk / 样本量 / 判据 / 签字人 |
| 七 · 成本与商业化 | 五段 TCO / 单客户成本 / 交付人天 / 替换成本 / 报价行数 |

| 项 | 规范 |

## 9. 反割裂三条自查

| # | 检查 | 不通过的表现 |
|---|---|---|
| 1 | 边栏每句在正文有出处 | 边栏出现了正文没有的判断或数字 |
| 2 | 决策现场出现「我们当时不知道 X」 | 全章决策都显得英明；管理者的痛点是信息不足，不是眼瞎 |
| 3 | 本章至少一处「我判断错过的一次」 | 通篇无失败，读者会判定这是宣传册 |

**写作红线**

① **不写任何公司实际情况**：不出现自家产品、数据、制度、客户、供应商、内部口径；② 不出现员工姓名与岗位之外的身份；③ 不对合规定性（不写「我们合规 / 不合规」），只写「标准要求 X，常见做法是 Y」。

## 10. 一页速查卡

| 序 | 动作 | 判据 |
|---|---|---|
| 1 | 写章首卡三行 | 问题 / 主张 / 代价，各一句 |
| 2 | 写引子，不给结论 | 引子最后一句不是判断句 |
| 3 | 写主论断 | 只有一句，≤40 字 |
| 4 | 写 3–4 组三段式 | 每组机理段去掉数字或条款后不成立 |
| 5 | 写决策现场 | ≥2 个选项 + 各自代价 + 谁拍的板 + 当时不知道什么 |
| 6 | 写代价与边界 | 给出"什么时候该反过来做" |
| 7 | 写边栏 2–3 个 | 三句式，每句正文有出处 |
| 8 | 写章末栏 | 判断句 2 条 / 代价 1 条 / 不可外包 3 条 |
| 9 | 横切篇加三域对照卡 | 三行都能填出差异，或说明为何不存在 |
| 10 | 标证据标签 | 每个关键数字后面有标签与出处 |
| 11 | 过反割裂三条 | 三条全过，不允许"基本符合" |
| 12 | 查字数 | ≤10,000 字；超了说明有两个主张 |
