# 《架构的代价》公开依据取证清单

> 替代原「缺口访谈提纲」· 不访谈内部，只检索公开来源
> 2026-11-06 · 老苏

---

## 0. 这份文件替代了什么

原 04 是七场内部访谈（运维 / 售后 / 质量 / 安全运营 / 法务 / 平台 / 采购），目的是拿到内部数字——在网设备数、OTA 成功率、故障率、告警闭环率、认证台账。

口径改为「不写任何公司实际情况」之后，这套访谈**整体失效**：访谈拿到的每个数字都不能进书。

但它要解决的问题还在：**书里要用的数字从哪来。** 这份清单就是那个问题的答案——把「问谁」换成「查哪」，把「访谈提纲」换成「检索任务」。

七个部门不必消失，角色变了：从**数据提供方**变成**成稿后的边界审稿人**——不提供数据，只判断「这段会不会被反推出公司」。这个活放在 M3 统稿阶段做，不占写作时间。

## 1. 取证总则

| # | 规则 | 判定 |
|---|---|---|
| 1 | 只取可公开核验的来源 | 读者能自己查到的才算；查不到的一律不进正文 |
| 2 | 每个数字带三件套 | 分母 + 时间窗 + 口径，缺一件不用 |
| 3 | 查不到就写明 | 写「公开资料有限，以下为常见做法」，不编、不借 |
| 4 | 一手优先 | 标准原文 > 官方公告 > 行业报告 > 媒体报道 |
| 5 | 记录检索路径 | 每个引用的来源、版本、检索日期，进 `引用台账` |

> **一条底线**：任何需要「我知道但查不到」才能成立的说法，降级为 `推演`，并写明假设。这不是退让，是这本书唯一的可信度来源。

## 3. 三块最难的

| 难点 | 为什么难 | 怎么办 |
|---|---|---|
| **商业化的报价与替换成本** | 几乎没有公开研究，企业也不公开报价 | 走「招标文件 + 计价规范 + 合同范本」三条路：门槛能从资格条款看出来，拆分粒度能从清单规范看出来，责任边界能从合同条款看出来。**不追求数字，只追求结构** |
| **质量篇的缺陷聚集研究** | 公开研究样本多在软件业，硬件侧少 | 软件侧引研究（标样本），硬件侧用「召回公告的结构」做归纳，不硬套 |
| **智能体篇的时效性** | 领域太新，结论半年就可能过期 | 每条结论标「版本 + 日期」；只讲机制不讲产品；基准只引「争议存在」不引排名 |

## 4. 检索记录模板

每个引用填一行，进 `引用台账.md`（写作时随章节增长）。

| 字段 | 填什么 |
|---|---|
| 编号 | C-001 起 |
| 来源类型 | 标准 / 法规 / 公告 / 研究 / 事故 |
| 名称与版本 | 全称 + 年份或版本号 |
| 位置 | 条款号 / 页码 / 章节 |
| 检索日期 | YYYY-MM-DD |
| 用在哪 | 章-节 |
| 一句话摘录 | 原文关键句（≤50 字） |
| 可核验链接 | 官方或稳定地址 |

## 5. 什么时候算「够用」

| 篇 | 达标线 |
|---|---|
| 一 互联网 | 每章至少 2 条标准/官方文档级引用 |
| 二 物联网 | 每章至少 1 条强制标准 + 1 条规范 |
| 三 智能体 | 每章至少 2 条规范/研究，全部标版本与日期 |
| 四 安全 | 每章至少 2 条清单/指南级引用 |
| 五 合规 | 每章至少 3 条可逐条引的法律条款 |
| 六 质量与测评 | 每章至少 2 条标准，抽样与质量模型必须原文 |
| 七 商业化 | 每章至少 2 份真实招标文件或合同范本，允许「结构够、数字缺」 |

> 达不到达标线的章节，**降字数，不降标准**。9,000 字写不出来就写 6,000，绝不用「应该」「通常」凑。
