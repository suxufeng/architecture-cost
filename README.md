## 关于案例

**本书不写任何一家公司的实际情况。** 没有内部数据、客户名、供应商型号、成本明细。

依据全部可查证：公开标准（ISO / IEC / GB）、法规条文、监管公告、公开事故报告、公开研究。需要现场感的段落用**复合场景**，由多个公开案例重构，文末注明构造方式。

每个关键数字带标签：`公开` / `引用` / `推演` / `场景`。

## 怎么参与

- **指出缺口**：哪一章漏了该回答的问题 → 开 Issue
- **纠正事实**：标准条款引错、推演假设不成立 → 提 PR，附条款号
- **补充公开来源**：更好的一手公开资料 → 附链接即可

不接受：要求补充某家公司的内部数据；要求把观点改得「更温和」。

## 写作约定

- 单章上限 10,000 字，写不下就拆或砍，不注水
- 每节必须能回答「所以你不该做什么」，没有否决项的节删掉
- 收口句只写判断，不写劝告
- 每章至少一处「我判断错过的一次」
